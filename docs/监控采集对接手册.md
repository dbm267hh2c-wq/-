# 监控采集对接手册

请按本文完成信息填报和采集器安装。只需在业务服务器上安装采集组件，**不要安装 Logstash、Elasticsearch、Kibana**。

需要覆盖的范围：

- 应用日志
- 服务器资源（CPU、内存、磁盘、网卡、进程）
- 应用端口 / 服务存活
- **业务接口地址**（完整 URL，需定期探测是否可访问）
- 数据库存活与性能
- 应用之间、服务器之间的调用链路

请先填完第 2 节表格并回传，再安装采集器。IP、端口、**接口地址**、数据库地址、调用关系缺一项，对应监控无法配置。

### 2.3 接口地址（必填，需探测检查）

请提供需要监控的全部业务接口，一行一个 URL。不要只写 IP 和端口。

| 序号 | 接口名称 | 所属应用 | 完整接口地址（含协议/域名或IP/端口/路径） | 方法 | 是否鉴权 | 期望状态码 | 期望响应关键字（可选） | 超时（秒） | 内外网 | 是否核心 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 订单健康检查 | 订单服务 | `http://10.0.0.21:8080/health` | GET | 否 | 200 | `"status":"UP"` | 5 | 内网 | 是 |  |
| 2 | 下单接口 | 订单服务 | `http://10.0.0.11:8080/api/order/create` | POST | 是 | 200 |  | 5 | 内网 | 是 | 探测请用只读或空跑接口 |
| 3 | 库存查询 | 库存服务 | `http://10.0.0.22:8080/api/stock/query` | GET | 否 | 200 |  | 5 | 内网 | 是 |  |
| 4 |  |  |  |  |  |  |  |  |  |  |  |

填写要求：

- 必须是可直接访问的完整地址，例如 `http://IP:端口/path` 或 `https://域名/path`，不要只写 `/api/xxx`。
- 健康检查、查询类接口优先；写操作、支付类不要作为常规探测，或提供专门的探测/空跑接口。
- 需要 Header、Token 的接口，在备注写明探测方式（固定探测账号 / 免鉴权健康检查路径），**不要把生产密钥写进本表长期留存**，密钥走加密通道。
- 期望状态码一般填 `200`。若接口正常时返回 `204` 或业务码在 JSON 里，请写清楚。
- 填完后请在能访问该接口的机器上先自检，通过后再配 Heartbeat：

```bash
# GET 示例，应返回期望状态码
curl -sS -o /tmp/api_body.txt -w "http_code=%{http_code} time=%{time_total}\n" \
  "http://10.0.0.21:8080/health"

# 需要 Header 时
curl -sS -o /tmp/api_body.txt -w "http_code=%{http_code}\n" \
  -H "Content-Type: application/json" \
  "http://10.0.0.22:8080/api/stock/query"

# HTTPS
curl -sS -o /tmp/api_body.txt -w "http_code=%{http_code}\n" \
  "https://example.com/api/health"
```

`http_code` 与表格中的期望状态码不一致，视为接口不可用，不要进入后续步骤。

## 3. 采集器怎么选

按机器角色安装，不要在业务机再装一层转发。

| 机器角色 | 安装组件 |
| --- | --- |
| 应用服务器 | Filebeat + Metricbeat + Heartbeat + 应用内 APM 探针 |
| 数据库服务器（允许安装） | Metricbeat（启用对应数据库模块）+ Heartbeat |
| 托管库 / 不能装采集器 | 在能连到该地址的业务机上做远程探测，并在 2.1 备注原因 |
| 只能发 syslog、不能装 Filebeat 的设备 | 将 syslog 发到 `172.28.65.248:514/udp`（同一份日志不要和 Filebeat 重复发） |

同一台机器上，Filebeat 与 Metricbeat 的 `name` 必须相同，建议都填 **业务 IP**。

## 5. Filebeat（应用日志）

### 5.1 安装

```bash
# CentOS / RHEL
yum install -y filebeat-8.19.19

# Ubuntu / Debian
apt-get install -y filebeat=8.19.19

filebeat modules disable system nginx mysql 2>/dev/null || true
systemctl stop filebeat
```

### 5.2 配置要点（只改 3 处）

配置文件：`/etc/filebeat/filebeat.yml`

```bash
cp /etc/filebeat/filebeat.yml /etc/filebeat/filebeat.yml.bak.$(date +%F)
```

将第 5.5 节内容覆盖进去后，只改：

| 配置项 | 怎么填 |
| --- | --- |
| `paths` | 本机真实日志路径，例如 `/app/logs/*.log` |
| `name` | 本机业务 IP（与服务器清单一致） |
| `output.logstash.hosts` | 保持 `["172.28.65.248:5044"]` |

不要打开 `output.elasticsearch`，不要配置 Kibana，不要开启 SSL。  
机器标识请写在 `name`，不要指望 `fields`、`tags` 作为来源标识。

### 5.3 多行日志

当前规则：行首为 `YYYY-MM-DD` 视为一条新日志，后续堆栈合并到上一条。

日志格式不同时，必须改 `parsers.multiline.pattern`，否则堆栈会被拆碎或粘成一条。

| 日志行首 | pattern |
| --- | --- |
| `2026-09-18 12:00:01` | `'^\d{4}-\d{2}-\d{2}'` |
| `2026/09/18` | `'^\d{4}/\d{2}/\d{2}'` |
| `[2026-09-18 12:00:01]` | `'^\[\d{4}-\d{2}-\d{2}'` |
| 单行日志、无堆栈 | 删除整个 `parsers` 段 |

### 5.4 注意

- `filestream` 的 `id` 用来记采集进度。同一批文件 **不要改 id**，也不要删除 `/var/lib/filebeat/registry`，否则会把历史日志重发一遍。
- Filebeat 必须能 **读取** 日志文件。常见失败是 `permission denied`。
- 一台机器只运行一个 Filebeat，不要两个进程盯同一批文件。
- 不要采集未经约定的 `/var/log/messages` 全量系统日志。

日志读权限示例：

```bash
setfacl -m u:filebeat:rx /data/monitor/server/logs
# 或
usermod -aG <日志所属组> filebeat
systemctl restart filebeat
```

### 5.5 可直接使用的 `filebeat.yml`

```yaml
filebeat.inputs:
- type: filestream
  id: app-logs
  enabled: true
  paths:
    - /data/monitor/server/logs/*.log   # 【必改】实际日志路径
  ignore_older: 72h
  parsers:
    - multiline:
        type: pattern
        pattern: '^\d{4}-\d{2}-\d{2}'   # 必须单引号；按实际日志行首修改
        negate: true
        match: after

filebeat.config.modules:
  path: ${path.config}/modules.d/*.yml
  reload.enabled: false

name: "请改成本机业务IP"

setup.template.enabled: false
setup.ilm.enabled: false
setup.dashboards.enabled: false
setup.kibana.enabled: false

output.elasticsearch:
  enabled: false

output.logstash:
  enabled: true
  hosts: ["172.28.65.248:5044"]
  bulk_max_size: 2048
  worker: 2
  compression_level: 3
  ttl: 30s
  pipelining: 2

processors:
  - add_host_metadata:
      when.not.contains.tags: forwarded
  - copy_fields:
      fields:
        - from: agent.name
          to: host.name
      fail_on_error: false
      ignore_missing: true
  - drop_fields:
      fields: ["cloud", "docker", "kubernetes"]
      ignore_missing: true

logging.level: info
logging.to_files: true
logging.files:
  path: /var/log/filebeat
  name: filebeat
  keepfiles: 7
  permissions: 0640
```

### 5.6 启动自检

```bash
filebeat test config -c /etc/filebeat/filebeat.yml
filebeat test output -c /etc/filebeat/filebeat.yml
systemctl enable --now filebeat
journalctl -u filebeat -f
```

`test output` 成功时应能连上 `172.28.65.248:5044`。  
日志中出现 `Harvester started for file` 表示已开始采集。

## 6. Metricbeat（主机 + 数据库）

### 6.1 安装

```bash
yum install -y metricbeat-8.19.19
# 或
apt-get install -y metricbeat=8.19.19
```

### 6.2 主机监控 `metricbeat.yml`

`name` 必须与本机 Filebeat 的 `name` 相同。

```yaml
name: "请改成本机业务IP"

metricbeat.config.modules:
  path: ${path.config}/modules.d/*.yml
  reload.enabled: false

output.elasticsearch:
  enabled: false

output.logstash:
  enabled: true
  hosts: ["172.28.65.248:5044"]

processors:
  - add_host_metadata: ~
  - copy_fields:
      fields:
        - from: agent.name
          to: host.name
      fail_on_error: false
      ignore_missing: true
  - add_fields:
      target: ''
      fields:
        beat_type: metricbeat

setup.template.enabled: false
setup.ilm.enabled: false
setup.kibana.enabled: false
```

启用系统模块：

```bash
metricbeat modules enable system
```

`/etc/metricbeat/modules.d/system.yml` 至少打开：

```yaml
- module: system
  period: 10s
  metricsets:
    - cpu
    - load
    - memory
    - network
    - process
    - process_summary
    - filesystem
    - fsstat
  process.include_top_n:
    by_cpu: 10
    by_memory: 10
```

### 6.3 数据库模块（按 2.4 表启用）

```bash
metricbeat modules enable mysql        # 或 postgresql / redis / mongodb
```

MySQL（`modules.d/mysql.yml`）：

```yaml
- module: mysql
  period: 10s
  hosts: ["user:password@tcp(数据库IP:3306)/"]
  metricsets: ["status", "galera_status"]
```

PostgreSQL：

```yaml
- module: postgresql
  period: 10s
  hosts: ["postgres://监控用户:密码@数据库IP:5432/postgres"]
  metricsets: ["activity", "bgwriter", "database"]
```

Redis：

```yaml
- module: redis
  period: 10s
  hosts: ["数据库IP:6379"]
  password: "只读或探测密码"
  metricsets: ["info", "keyspace"]
```

配置文件权限：

```bash
chmod 600 /etc/metricbeat/metricbeat.yml /etc/metricbeat/modules.d/*.yml
```

托管数据库不能在库机安装时：在一台能连到该库的业务机上启用上述模块，远程采集。

### 6.4 启动自检

```bash
metricbeat test config
metricbeat test output
systemctl enable --now metricbeat
```

## 7. Heartbeat（应用端口 + 接口地址探活）

按第 2.2 节探测 **端口**，按第 2.3 节探测 **完整接口地址**，按第 2.4 节探测数据库端口。  
`id`、`name` 需与调用关系表、接口表中的名称对应。

**端口探测和接口探测都要配。** 只探 TCP 端口时，应用进程在、接口 500 也会被当成正常。

```yaml
name: "heartbeat-本环境"

output.elasticsearch:
  enabled: false

output.logstash:
  enabled: true
  hosts: ["172.28.65.248:5044"]

processors:
  - add_fields:
      target: ''
      fields:
        beat_type: heartbeat

heartbeat.monitors:
  # —— 接口地址检查（来自第 2.3 节，必须用完整 URL）——
  - type: http
    id: order-health
    name: 订单健康检查
    urls: ["http://10.0.0.21:8080/health"]
    schedule: "@every 30s"
    timeout: 5s
    check.response:
      status: [200]
      body: '"status":"UP"'     # 无关键字要求可删除本行

  - type: http
    id: stock-query
    name: 库存查询
    urls: ["http://10.0.0.22:8080/api/stock/query"]
    schedule: "@every 30s"
    timeout: 5s
    check.response:
      status: [200]

  # HTTPS 接口示例
  # - type: http
  #   id: gateway-health
  #   name: 网关健康检查
  #   urls: ["https://example.com/api/health"]
  #   ssl.verification_mode: full
  #   schedule: "@every 30s"
  #   timeout: 5s
  #   check.response:
  #     status: [200]

  # 需要 Header 的接口（Token 不要明文长期写在可随意转发的文件里）
  # - type: http
  #   id: order-query
  #   name: 订单查询
  #   urls: ["http://10.0.0.11:8080/api/order/query"]
  #   timeout: 5s
  #   schedule: "@every 30s"
  #   check.request:
  #     method: GET
  #     headers:
  #       Authorization: "Bearer 探测用token"
  #   check.response:
  #     status: [200]

  # —— 端口探活（来自第 2.2 / 2.4 节）——
  - type: tcp
    id: order-mysql
    name: 订单库
    hosts: ["10.0.0.31:3306"]
    schedule: "@every 30s"
    timeout: 5s

  - type: tcp
    id: order-redis
    name: 库存Redis
    hosts: ["10.0.0.32:6379"]
    schedule: "@every 30s"
    timeout: 5s
```

配置前，对第 2.3 节每一个接口先执行 `curl` 自检，状态码与期望值一致后再写入 Heartbeat。

安装与启动：

```bash
yum install -y heartbeat-elastic-8.19.19
# 部分系统包名为 heartbeat-elastic，请以仓库实际名称为准

heartbeat test config
heartbeat test output
systemctl enable --now heartbeat-elastic
```

说明：可在每台机器探测本机端口和接口；机器较多时也可只在一台能访问全部目标 URL 的服务器上集中部署。集中部署时，必须能访问第 2.3 节列出的全部接口地址。

## 8. 调用链路（应用内埋点）

主机指标和端口探活 **看不到**「A 调用了 B」。要采集调用链，必须在应用中安装 APM / OpenTelemetry 探针。

### 8.1 开发配合事项

| 项 | 要求 |
| --- | --- |
| 语言 / 框架 | Java / Go / Python / Node 等，按官方 APM Agent 接入 |
| `service.name` | 与第 2.6 节「应用名称」完全一致 |
| `environment` | 与第 2.1 节环境一致，如 `prod` / `test` |
| 上报地址 | 使用另行提供的 APM 地址，不要报到本机或其他 ES |
| 跨服务串链 | 保留 HTTP/RPC 头中的 `traceparent`（W3C） |
| 采样率 | 生产建议先 `0.1`～`0.2` |
| 敏感信息 | 关闭请求体全量采集，脱敏 Header、SQL 参数 |

Java 启动参数示例：

```bash
java -javaagent:/opt/elastic-apm-agent.jar \
  -Delastic.apm.service_name=order-service \

  -Delastic.apm.application_packages=com.example.order \
  -Delastic.apm.server_url=http://APM地址:8200 \
  -Delastic.apm.secret_token=对接后提供 \
  -Delastic.apm.transaction_sample_rate=0.2 \
  -jar order-service.jar
```

`service.name`、端口表、接口地址表、调用关系表必须对齐，否则拓扑对不上。

## 11. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `connection refused` / `test output` 失败 | 5044 未放行，或地址填错 | 核对 `172.28.65.248:5044`，先做 `nc -vz` |
| `i/o timeout` | 中间防火墙丢包 | 明确放行 TCP 5044 |
| 启动后无日志 | 路径不对、没有新日志、被 `ignore_older` 过滤 | 确认文件有新行；可临时去掉 `ignore_older` |
| `permission denied` | 读不到日志文件 | ACL 或把 filebeat 用户加入日志组 |
| 堆栈被拆成多条 / 多条粘成一条 | 多行 pattern 不匹配 | 按 5.3 修改 |
| 历史日志突然全量重发 | 改了 `filestream.id` 或清理了 registry | 不要改 id，不要删 registry |
| 只有日志，没有 CPU / 内存 | 未安装 Metricbeat，或未启用 `system` | 按第 6 节安装 |
| 端口挂了但没有探测记录 | Heartbeat 未配置该端口 | 按 2.2 表补 TCP monitor |
| 端口通但接口 500/超时 | 只探了端口，未探完整 URL | 按 2.3 表补 HTTP monitor，并用 `curl` 复核 |
| 接口探测 401/403 | 未提供免鉴权健康检查或探测账号 | 补健康检查路径，或走加密通道提供探测凭证 |
| 接口探测一直失败 | URL 不完整、只能内网访问、证书问题 | 填完整 `http(s)://主机:端口/path`；确认探测机能访问；HTTPS 核验证书 |
| 数据库只有端口通，没有连接数 | 未给只读账号，只做了 TCP 探测 | 按 2.4 启用数据库模块 |
| 看不到 A 调用 B | 未埋 APM，或 `service.name` 不一致 | 按第 8 节接入并对齐名称 |
| 日志和指标对不上同一台机器 | Filebeat 与 Metricbeat 的 `name` 不同 | 统一成业务 IP |
